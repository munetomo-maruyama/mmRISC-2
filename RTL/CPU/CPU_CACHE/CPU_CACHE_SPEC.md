- 版: Rev-1 (2026-09-19) 初版

## 1. 目的と範囲

CPUコア(パイプライン)とMMUはこの後のフェーズで実装する。本フェーズでは**L1命令キャッシュとL1データキャッシュ**を作り、
既存のメモリバス(AXI4)・周辺バス(AXI4-Lite)へ接続して、BFMとFPGA上のOpenOCDメモリアクセスで検証する。

| 項目 | 本フェーズ |
|---|---|
| L1命令キャッシュ (I$) | **本実装** |
| L1データキャッシュ (D$) | **本実装** |
| 非キャッシュアクセス経路 | **本実装**(周辺バスおよびキャッシュ対象外領域) |
| AMO / LR-SC (A拡張) | **本実装**(D$内で処理) |
| fence / fence.i によるフラッシュ・無効化 | **本実装**(制御ポート) |
| デバッグアクセスの一貫性 | **本実装**(4.7、デバッグをキャッシュ経由にする) |
| MMU (Sv39) / TLB | 次フェーズ。本フェーズは接続点のみ用意(3.3) |
| L2キャッシュ | 実装しない(CPUブロック完成後に検討。Arty A7-100TのBRAM量では512KiBは載らない) |
| Zicbom などのキャッシュ管理命令 | 実装しない(将来) |
| ECC / パリティ | 実装しない |

## 3. パラメータ

### 3.1 既定値(Rocket `linux` と同等)

| パラメータ | 既定値 | 内容 |
|---|---|---|
| `PADDR_WIDTH` | 40 | 物理アドレス幅。**CPU_TOP の `AXI4_ADDR_WIDTH` に合わせる**(タグアレイの幅もこれで決まる) |
| `VADDR_WIDTH` | 39 | 仮想アドレス幅(Sv39)。MMU未実装時は実効アドレス=物理アドレス |
| `XLEN` | 64 | |
| `BUS_DATA_WIDTH` | 64 | メモリバスのデータ幅(ビート幅) |
| `IC_SETS` | 64 | 命令キャッシュのセット数 |
| `IC_WAYS` | 4 | 命令キャッシュのウェイ数 |
| `IC_BLOCK_BYTES` | 64 | 命令キャッシュのブロックサイズ |
| `IC_MSHRS` | 2 | 命令キャッシュの同時ミス数 |
| `DC_SETS` | 64 | データキャッシュのセット数 |
| `DC_WAYS` | 4 | データキャッシュのウェイ数 |
| `DC_BLOCK_BYTES` | 64 | データキャッシュのブロックサイズ |
| `DC_MSHRS` | 4 | データキャッシュの同時ミス数 |
| `DC_WB_ENTRIES` | 2 | 書き戻しバッファのエントリ数 |
| `REPLACE_POLICY` | `RANDOM` | 置換方式。`RANDOM`(LFSR) または `PLRU` |
| `MEM_BASE` | `0x00_8000_0000` | この値以上がキャッシュ対象(メモリバス)、未満は非キャッシュ(周辺バス) |
| `IC_AXI4_ID` | 2 | 命令キャッシュのAXI4 ID(デバッグ=1、BFM=0と区別) |
| `DC_AXI4_ID_BASE` | 4 | データキャッシュのAXI4 ID起点。MSHRごとに `BASE + n` を使う |

既定値では I$ = 64セット × 4ウェイ × 64B = **16 KiB**、D$ も同じく **16 KiB**。

### 3.2 パラメータの制約(合成前に `assert` で検査)

1. `SETS`、`WAYS`、`BLOCK_BYTES` は2のべき乗。
2. `BLOCK_BYTES` は `BUS_DATA_WIDTH/8` の整数倍(既定では 64B = 8ビート)。
3. **`SETS * BLOCK_BYTES <= 4096`**(VIPT のエイリアス防止。4.1参照)
   - 既定値: 64 × 64 = 4096 でちょうど上限。
   - 容量を増やすときは**ウェイ数**で増やす(例: 8ウェイで32KiB)。
4. `MSHRS >= 1`。`DC_AXI4_ID_BASE + DC_MSHRS - 1` が `AXI4_ID_WIDTH` に収まること。
5. `PADDR_WIDTH` は `CPU_TOP` の `AXI4_ADDR_WIDTH` と同じ値。

### 3.3 アドレスの分解

物理アドレス幅 `PADDR_WIDTH`(既定40)を次のように分ける。

```
  PADDR_WIDTH-1                    IDX_MSB        OFS_MSB         0
 ┌──────────────────────────────┬──────────────┬─────────────────┐
 │            タグ               │  インデックス │  ブロック内オフセット │
 └──────────────────────────────┴──────────────┴─────────────────┘
   TAG_BITS = PADDR_WIDTH         IDX_BITS        OFS_BITS
              - IDX_BITS - OFS_BITS = $clog2(SETS)  = $clog2(BLOCK_BYTES)
```

既定値では OFS_BITS=6、IDX_BITS=6、**TAG_BITS = 40 - 6 - 6 = 28**。

- タグアレイ1エントリ = タグ(28) + valid(1) [+ dirty(1) : D$のみ] = I$ 29bit、D$ 30bit。
- `PADDR_WIDTH` を変えるとタグ幅が自動的に追従する。

## 4. 動作仕様

### 4.1 インデックス方式 (VIPT)

- インデックスとブロック内オフセットは**仮想アドレスの下位ビット**から取る。
  `SETS * BLOCK_BYTES <= 4096` なので、これらはページ内オフセット(Sv39 で変換されないビット)に収まる。
- タグ比較には**TLBが返す物理アドレス**を使う。TLB引きとタグアレイ読み出しを同じサイクルに並列実行できる。
- 同一物理ページが別インデックスに載ること(エイリアス)は、上記制約により発生しない。
- MMU未実装の本フェーズでは、TLB相当の入力に実効アドレスをそのまま物理アドレスとして与える。

### 4.2 キャッシュ対象領域

| アドレス | 扱い |
|---|---|
| `MEM_BASE` 以上 | キャッシュ対象。メモリバス(AXI4) |
| `MEM_BASE` 未満 | 非キャッシュ。周辺バス(AXI4-Lite)へ素通し |

- 非キャッシュアクセスは、キャッシュを参照せず、アクセス幅そのままで周辺バスへ出す(既存のデバッグバスマスタと同じレーン規則)。
- 非キャッシュのストアは、順序保証のため、先行するキャッシュ書き戻しの完了を待ってから発行する。
- 将来PMA(Physical Memory Attributes)表を追加する場合も、この判定を差し替えるだけで済む構成にする。

### 4.3 読み出し

1. インデックスでタグアレイとデータアレイを引き、TLBの物理タグと全ウェイを比較する。
2. **ヒット**: 該当ウェイのデータを返す(1サイクル)。
3. **ミス**: MSHRを1つ確保し、リフィル要求を出す。
   - AXI4: `ARBURST=INCR`、`ARSIZE=3`(8バイト)、`ARLEN = BLOCK_BYTES/8 - 1`(既定7)、`ARADDR` = ブロック先頭。
   - 要求されたワードが届いた時点で、待っている要求へ先に返す(アーリーリスタート)。
   - ブロック全体が届いたらデータアレイとタグアレイを更新する。

### 4.4 書き込み(D$、ライトバック + ライトアロケート)

1. **ヒット**: データアレイの該当バイトのみ更新し、dirty を立てる。
2. **ミス**: ライトアロケート。リフィル完了後に書き込みを適用する。
3. **追い出し**: 置換対象が dirty の場合、ブロック全体を書き戻しバッファへ移し、AXI4へ書き出す。
   - `AWBURST=INCR`、`AWSIZE=3`、`AWLEN = BLOCK_BYTES/8 - 1`、`WSTRB` は全バイト有効。
   - 書き戻しはリフィルと並行して進めてよい(バッファがあるため、リフィル待ちを書き戻しで止めない)。

### 4.5 ミス処理(ノンブロッキング、MSHR)

- ミス中も、**他のライン**へのヒットアクセスは受け付ける(ヒット下ミス、ミス下ミス)。
- **同一ラインへの後続ミスはMSHRにマージ**し、バス要求は1回だけにする。
- MSHRが全て埋まっている、または書き戻しバッファが満杯のときは、その要求を待たせる。
- **AXI4 IDの割り当て**: MSHRごとに固有のIDを使う(`DC_AXI4_ID_BASE + n`)。
  - 同一IDのトランザクションは順序が保証され、異なるID間は順不同で返ってよい。返ってきたIDでMSHRを特定する。
  - 命令キャッシュは `IC_AXI4_ID` を共有し、MSHR数だけ未処理を出す場合は順序保証に依存する。
- 同一アドレスに対する読み書きの順序は、MSHRとストアの依存判定で保つ。

### 4.6 AMO / LR-SC

- D$内で処理する。対象アドレスがキャッシュ対象領域であることを前提とする。
- **AMO**: ヒットなら読み出し→演算→書き込みを不可分に行い、dirty を立てる。ミスならライトアロケート後に実行する。
- **LR/SC**: 予約レジスタを1組持つ(物理アドレスのブロック単位)。
  - LR で予約し、SC は予約が生きていれば成功(0を返す)、無効なら失敗(1を返す)。
  - 予約は、他マスタからの同一ブロックへの書き込み、追い出し、割り込み、別アドレスのLR で無効化する。
- 非キャッシュ領域へのAMO/LR-SCは対応しない(アクセスフォールト)。

### 4.7 デバッグアクセスの一貫性

デバッグ論理(SBA / Access Memory)のメモリアクセスを、`BUS_ARB` 直結から**キャッシュ経由**に変更する。

| 種別 | 動作 |
|---|---|
| デバッグ読み出し | D$を参照する。ヒットならキャッシュの値(最新値)を返す。ミスならリフィルせずにバスから直接読む(非アロケート) |
| デバッグ書き込み | D$がヒットしていれば該当ラインを更新(dirty)。ミスならバスへ直接書く(非アロケート)。**いずれの場合もI$の該当ラインを無効化する** |
| キャッシュ対象外 | これまでどおり周辺バスへ直接アクセス |

- これにより、OpenOCD からブレークポイント命令を書き込んだ場合も、I$に古い命令が残らない。
- デバッグ用のポートはD$に専用ポートとして追加し、CPUのロード/ストアと調停する(CPU優先)。
- CPUコア実装前の現在は、デバッグ論理は `BUS_ARB` 直結のままとし、CPUブロック実装時にこの接続へ切り替える。

### 4.8 フラッシュと無効化

制御ポートで次の操作を受け付ける(CPUコアの `fence` / `fence.i` 実行時、およびデバッグ書き込み時に使う)。

| 操作 | 対象 | 内容 |
|---|---|---|
| `IC_INVAL_ALL` | I$ | 全ライン無効化 |
| `IC_INVAL_LINE` | I$ | 指定アドレスのライン無効化 |
| `DC_FLUSH_ALL` | D$ | dirty ラインを全て書き戻し、無効化する |
| `DC_FLUSH_LINE` | D$ | 指定アドレスのラインを書き戻し、無効化する |
| `DC_DRAIN` | D$ | 書き戻しバッファと未処理アクセスの完了待ち(`fence` 用) |

各操作は完了通知を返す。リセット直後は全ラインを無効化した状態から始める(タグアレイのvalidをクリア)。

## 5. インタフェース

### 5.1 CPUコア側(命令フェッチ)

| 信号 | 方向 | 内容 |
|---|---|---|
| `if_req_valid` / `if_req_ready` | in / out | フェッチ要求 |
| `if_req_vaddr[VADDR_WIDTH-1:0]` | in | 仮想アドレス |
| `if_paddr[PADDR_WIDTH-1:0]` / `if_paddr_valid` | in | TLBが返す物理アドレス(同サイクル)。MMU未実装時は実効アドレス |
| `if_kill` | in | 分岐などによる要求の取り消し |
| `if_resp_valid` | out | 応答有効 |
| `if_resp_data[63:0]` | out | 命令データ |
| `if_resp_fault` | out | バスエラー(アクセスフォールト) |

| 信号 | 方向 | 内容 |
|---|---|---|
| `ls_req_valid` / `ls_req_ready` | in / out | アクセス要求 |
| `ls_req_vaddr` / `ls_paddr` | in | 仮想/物理アドレス |
| `ls_req_op[2:0]` | in | LOAD / STORE / AMO / LR / SC |
| `ls_req_size[1:0]` | in | 1/2/4/8バイト |
| `ls_req_signed` | in | 符号拡張 |
| `ls_req_wdata[63:0]` | in | 書き込みデータ |

### 5.3 制御ポート

| 信号 | 方向 | 内容 |
|---|---|---|
| `cc_req_valid` / `cc_req_ready` | in / out | 4.8 の操作要求 |
| `cc_req_op[2:0]` / `cc_req_addr` | in | 操作種別とアドレス |
| `cc_done` | out | 完了 |

### 5.4 バス側

既存の `CPU_TOP` の AXI4 / AXI4-Lite マスタポートへ、`BUS_ARB` 経由で接続する。デバッグ論理と同じ調停に入る。

## 6. 物理実装の見積もり(Arty A7-100T)

| 用途 | 構成 | BRAM |
|---|---|---|
| I$ データ | 4ウェイ × 4KiB | 4 タイル(ウェイごとにRAMB36) |
| I$ タグ | 64 × (4 × 29bit) | 1 タイル(またはLUTRAM) |
| D$ データ | 4ウェイ × 4KiB | 4 タイル |
| D$ タグ | 64 × (4 × 30bit) | 1 タイル |
| 合計 | | **約10タイル**(135タイル中) |

Rocket `linux` のL1が実測12タイル(RAMB36×8 + RAMB18×8)なので、同等の規模になる。
容量を増やす場合(8ウェイ 32KiB ×2)は約20タイルとなり、これも収まる。

## 8. 決定事項

| # | 項目 | 決定 |
|---|---|---|
| 1 | 既定構成 | Rocket `linux` と同等(I$/D$ とも 16KiB = 64セット × 4ウェイ × 64Bブロック) |
| 2 | パラメータ化 | セット数・ウェイ数・ブロックサイズを I$/D$ 別に指定可能 |
| 3 | タグアレイのアドレス幅 | CPU側の物理アドレス幅(`PADDR_WIDTH`、既定40)に追従 |
| 4 | インデックス方式 | VIPT。`SETS × BLOCK_BYTES <= 4096` に制限し、容量増加はウェイ数で行う |
| 5 | 書き込み方針 | ライトバック + ライトアロケート |
| 6 | ミス処理 | ノンブロッキング(MSHR付き、既定 I$2 / D$4) |
| 7 | デバッグ一貫性 | デバッグアクセスをキャッシュ経由にする。書き込み時はI$該当ラインを無効化 |
| 8 | 置換方式 | パラメータ(既定 RANDOM) |
| 9 | L2キャッシュ | 本フェーズでは実装しない |
