- 版: Rev-1 (2026-09-20) 初版(設計計画)

## 1. 目的と範囲

LiteX + Linux を Arty A7-100T で動かすための **RV64GC + Sv39** コア。
デバッグ論理と L1 キャッシュは実装・検証済みで、本仕様はその間に入る
CPU コア本体を定義する。

```
        CPU_TOP
  ┌──────────────────────────────────────────────┐
  │  CPU_CORE (本仕様)                            │
  │    フロントエンド ─ ITLB ─┐                   │
  │    バックエンド   ─ DTLB ─┤                   │
  │    CSR / 例外 / CLINT     │                   │
  └───────────────────────────┼──────────────────┘
                              │ i_*/d_* (5章)
                        CPU_CACHE ── BUS_ARB ── AXI4 / AXI4-Lite
                              ▲
                        CPU_DBG(ハート制御・D$ 経由のメモリアクセス)
```

本フェーズで置き換わるもの: `CPU_BFM`(BFM)、`DBG_HART_STUB`(疑似ハート)、
`CPU_TOP` の `u_bus_arb_cpu`(BFM 生バス用の調停)。

## 2. 命令セット

### 2.1 本実装の範囲(Rocket `linux` 構成と同等)

| 項目 | 内容 |
|---|---|
| 基本 | RV64I |
| 標準拡張 | M(乗除算)、A(AMO/LR-SC)、F/D(単精度・倍精度)、C(圧縮命令) |
| 付随 | Zicsr、Zifencei、Zicntr(`mcycle`/`minstret`) |
| 特権 | M / S / U、Sv39(3 段ページテーブル、4KiB/2MiB/1GiB) |
| `misa` | `0x8000_0000_0014_112d`(= A,C,D,F,I,M,S,U。CPU_TOP のパラメータ、読み出し専用) |

### 2.2 あとから足せるようにしておくもの

| 追加候補 | 今やっておくこと |
|---|---|
| B 拡張(Zba/Zbb/Zbs) | デコーダを**拡張ごとのテーブル**に分け、未定義は既定で不正命令例外に落とす |
| V 拡張(ベクタ) | オペコード `OP-V (0x57)` と `vset*` を予約。**長レイテンシ・順不同完了**を扱える発行/完了インタフェースを最初から用意する(最初の利用者は FDIV/FSQRT) |
| カスタム命令 | `custom-0/1/2/3`(0x0B/0x2B/0x5B/0x7B)をデコーダから**アクセラレータポート**へ横流し(9章) |
| Zicbom 等 | キャッシュに `FLUSH`/`fence.i` はあるので、ライン単位操作を追加する形 |

デコーダの出力は 1 本の `uop` レコード(rs1/rs2/rd/imm/機能ユニット/例外)に統一し、
機能ユニットを足してもパイプライン制御を触らずに済むようにする。

## 3. パイプライン

### 3.1 前提となる実測値

| 経路 | レイテンシ | スループット |
|---|---|---|
| I$ ヒット | 要求サイクル N → 命令が見えるのは **N+2** | 1 フェッチ/サイクル |
| D$ ヒット | 要求サイクル N → データが見えるのは **N+3**(ROB 1 段を含む) | 1 アクセス/サイクル |
| I$ ミス | 13 サイクル | |
| D$ ミス | 12(fill)/ 22(ダーティ追い出し) | |

FPGA 実測(Arty A7-100T、2026-09-20)では D$ ヒット経路(タグ RAM → ヒット判定
→ `rob_data`、論理 12 段)が 15.5ns で、**50MHz なら 4.4ns 余裕、100MHz は不可**。

### 3.2 構成(50MHz 目標、6 段 + フェッチキュー)

```
 IF1 : PC 選択 / ITLB 引き / I$ 索引(仮想アドレス)
 IF2 : I$ タグ比較(ITLB の物理タグ)・ウェイ選択 → フェッチキューへ
 (FQ): フェッチキュー(4〜8 エントリ、RVC 整列、デカップリング)
 ID  : RVC 展開 / デコード / レジスタ読み出し / ハザード判定
 EX  : ALU・分岐判定・アドレス生成(AGU)+ DTLB 引き
 MA  : D$ 索引(物理アドレス)、ストアデータ整列
 WB  : D$ タグ比較・ウェイ選択の結果を受けて書き戻し / フォワード
```

- **TLB は EX に同居させる**(AGU の加算 → TLB 引きを 1 サイクル)。こうすると
  直列方式でも**段数は並列 VIPT と同じ**になり、差は EX のクリティカルパスだけ
  になる。50MHz(20ns)なら 64bit 加算 + 小容量 TLB で収まる見込み。
- 命令側は、次フェッチアドレス(PC+4 または BTB の予測先)が 1 サイクル前に
  分かるので、**ITLB 引きを前倒し**して順次フェッチではペナルティを出さない。
- ロードユース: D$ が現状の 3 サイクルなら**2 バブル**、キャッシュにヒット時
  ROB バイパス(4.4)を入れて 2 サイクルにすれば**1 バブル**。
- 分岐: EX で解決。予測器なしの初期版は成立分岐ごとに **3 サイクル**
  (IF1/IF2/ID の再充填)。BTB + 2bit 予測器を入れれば予測ミス時のみ。

### 3.3 100MHz を狙う場合(将来)

| 長い経路 | 対策 |
|---|---|
| D$ ヒット(タグ比較 → ウェイ選択 → 整列、実測 15.5ns) | ウェイ選択を段分け、またはウェイ予測 |
| EX(加算 + DTLB) | DTLB を独立段にする(段数 +1)か、並列 VIPT に移行(段数そのまま) |

並列 VIPT へ移行する準備として、キャッシュのインタフェースは既に
**索引用アドレスと物理アドレスの 2 本**に分けてある(5.2)。

## 4. フロントエンド

### 4.1 フェッチキュー(プリフェッチキュー)

**入れる。** 理由:

1. I$ ミス(13 サイクル)やバックエンド停止をキューが吸収し、フェッチが先行できる。
2. **RVC**: 16bit 命令があるため 64bit フェッチ境界をまたぐ命令が出る。半端な
   ハーフワードを保持する場所が必要で、キューが自然な置き場になる。
3. プリデコード(RVC 展開、分岐検出、将来の BTB 更新)の置き場になる。

| 項目 | 既定 |
|---|---|
| 深さ | 4 エントリ(64bit フェッチワード + PC)、パラメータ化 |
| 整列 | キュー出口で RVC 展開。境界跨ぎは次エントリと連結 |
| フラッシュ | 分岐リダイレクト・例外・`fence.i`・デバッグ停止で全破棄 |

予測器を入れるまでは深さ 4 で十分(成立分岐で毎回捨てるため)。BTB 追加後に
8 まで増やす余地を残す。

### 4.2 分岐予測

初期版は**静的(常に not-taken)**。M6 で BTB(直接写像 32〜64 エントリ)と
2bit 飽和カウンタを IF1 に追加し、リダイレクトを予測ミス時のみにする。

## 5. メモリインタフェース

### 5.1 キャッシュへの接続

`CPU_CACHE_SPEC.md` 5 章のポートをそのまま使う。コアが出すのは

- 命令: `i_req_valid/ready/addr`、`i_resp_valid/data/error`、`i_flush_*`、`i_kill`
- データ: `d_req_valid/ready/addr/size/cmd/wdata`、`d_resp_valid/data/error`

### 5.2 物理アドレスポート(MMU の差し込み口)

`i_req_paddr` / `d_req_paddr` は、**要求が受理された次のサイクル**(その要求が
キャッシュのステージ 1 にいるサイクル)に有効であること。索引とオフセットは
`*_req_addr` から、タグは `*_req_paddr` から取る。

| 方式 | コアの出し方 |
|---|---|
| MMU なし(現在) | `*_req_addr` を 1 サイクル遅らせて `*_req_paddr` に出す |
| 直列(本フェーズ) | EX で TLB を引き、その物理アドレスを MA の次サイクルに出す |
| 並列 VIPT(将来) | 索引は仮想アドレス、TLB 出力をそのまま `*_req_paddr` へ |

並列 VIPT を使う場合は **`SETS × BLOCK ≤ 4096`**(索引+オフセットがページ内に
収まること)。既定構成 64 セット × 64B = 4096 はちょうど上限で、容量を増やす
ときはウェイ数で増やす。

### 5.3 fence 系

| 命令 | 動作 |
|---|---|
| `fence` | D$ に `FENCE`(未完了バスアクセスの完了待ち) |
| `fence.i` | I$ に `i_flush_valid`(全ライン無効化)。先に D$ の `FLUSH` が必要 |
| `sfence.vma` | TLB(ITLB/DTLB)の無効化。キャッシュには影響しない |
| `FLUSH` | キャッシュ全体の書き戻し + 無効化(リセット前・デバッグ用) |

## 6. MMU と保護 (`RTL/CPU/CPU_MMU`)

`CORE_MMU` がパイプラインと 2 つのキャッシュポートの間に入る。各面は仮想アドレス
を渡し、物理アドレスか、フォールトか、「まだ出せない」(ページテーブルウォーク中)
のいずれかを受け取る。

### 6.1 構成

| ブロック | 役割 |
|---|---|
| `MMU_PMP` | 物理メモリ保護。組み合わせ回路。命令用とデータ用に 1 基ずつ |
| `MMU_TLB` | ITLB / DTLB。フルアソシアティブ、パラメータ化 |
| `MMU_PTW` | ページテーブルウォーカ 1 基を ITLB/DTLB で共有。D$ 経由で読む |
| `CORE_MMU` | 上記をまとめ、D$ ポートを LSU と PTW で調停する |

### 6.2 Sv39

| 項目 | 内容 |
|---|---|
| 方式 | Sv39、4KiB / 2MiB / 1GiB ページ |
| 権限 | `satp`(MODE/ASID/PPN)、`mstatus` の MPRV/MPP/SUM/MXR、U/S/X/W/R/A/D |
| 例外 | instruction/load/store page fault(12/13/15) |
| 無効化 | `sfence.vma`。rs1 がアドレス、rs2 が ASID、0 はそれぞれ「全部」 |
| A/D ビット | **ハードウェア更新はしない**。A=0(または書き込みで D=0)は
  ページフォールトにして OS に任せる(Svade)。Linux はこの方式に対応している |

### 6.3 パイプラインとのつなぎ

TLB ヒット時の変換は**組み合わせ**で、要求を出すのと同じサイクルに物理アドレスが
出る。キャッシュは**仮想アドレスで索引し、物理アドレスでタグを引く**(5.2 の
「並列 VIPT」)。索引とオフセットがページ内に収まる(`SETS × BLOCK ≤ 4096`)ので
両者はその範囲で一致し、キャッシュ側には手を入れない。

- **命令面**: フェッチは投機的なので、フォールトをその場で例外にはしない。
  パーセルと一緒にキューに書き込み、それを実際に使う命令が ID で例外にする。
  フォールトしたフェッチはキャッシュに出さず、IFU の中で応答を作る。
  ミス中(ウォーク中)はフェッチを出さない。
- **データ面**: EX でアドレスが出たところで引く。フォールトはその場で例外、
  ミス中は EX をストールさせる。

### 6.4 PMP

| 項目 | 内容 |
|---|---|
| エントリ数 | 16(`PMP_ENTRIES`、0 で機能ごと削除) |
| モード | OFF / TOR / NA4 / NAPOT |
| 判定 | **番号の一番小さい一致エントリが決める**。許可でも拒否でもそれで終わり |
| 一致なし | M は通る、S と U は通らない |
| ロック | `L` が立つとリセットまで変更不可。M もそのエントリに縛られる |
| 幅のある転送 | 先頭バイトと末尾バイトを見て、**同じエントリに入っていなければ拒否** |

`pmpaddr` はアドレスを 2 ビット右シフトして持つので最小領域は 4 バイト。
データ面の特権は `mstatus.MPRV` が立っていれば `MPP`、そうでなければ現在の特権。
命令フェッチは MPRV の影響を受けない。

**S/U に降りるファームウェアは必ず 1 本はエントリを書く必要がある**
(riscv-tests の p 環境が `pmpaddr0 = -1`、`pmpcfg0 = NAPOT|R|W|X` を置くのと同じ)。
本プロジェクトのテストでは `tests/test.h` の `INIT_PMP` がこれをやる。

MMU は**コアが M-mode で動いたあと**に載せた(12 章)。

## 7. レジスタと CSR

| 種別 | 内容 |
|---|---|
| GPR | x0-x31、64bit。2 読み出し 1 書き込み(FPGA では分散 RAM 2 面 or BRAM) |
| FPR | f0-f31、64bit(D 拡張)。3 読み出し 1 書き込み、NaN-boxing(10 章) |
| CSR | M-mode: `mstatus/misa/mie/mtvec/mscratch/mepc/mcause/mtval/mip/mcycle/minstret/mhartid/mvendorid/marchid/mimpid` ほか |
| | S-mode: `sstatus/sie/stvec/sscratch/sepc/scause/stval/sip/satp` |
| | 委譲: `medeleg/mideleg` |
| | デバッグ: `dcsr/dpc/dscratch0/1`(デバッグ論理と共有) |

CSR ファイルはアドレス → レジスタのテーブル駆動にして、拡張追加時に行を足す
だけで済むようにする。未実装 CSR へのアクセスは不正命令例外。

実装済み(`CORE_CSR`)。マシンモード:

| アドレス | CSR | 備考 |
|---|---|---|
| 0x300 | `mstatus` | MIE/SIE/MPIE/SPIE/MPP/SPP/FS/MPRV/SUM/MXR/TVM/TW/TSR/UXL/SXL/SD |
| 0x301 | `misa` | MXL=2、IMAFDC + S + U。書き込みは無視 |
| 0x302 / 0x303 | `medeleg` / `mideleg` | 委譲。11 番(M からの ECALL)と予約番号は書けない |
| 0x304 / 0x344 | `mie` / `mip` | M と S の 3 本ずつ。M の pending は CLINT・PLIC が駆動 |
| 0x305 | `mtvec` | モード 0(direct)と 1(vectored)。予約モードは取り込まない |
| 0x306 | `mcounteren` | S/U がカウンタを読めるかどうか |
| 0x340-0x343 | `mscratch` / `mepc` / `mcause` / `mtval` | `mepc` は下位 1bit を落とす |
| 0x3A0 / 0x3A2 | `pmpcfg0` / `pmpcfg2` | PMP 設定、1 本に 8 エントリ |
| 0x3B0-0x3BF | `pmpaddr0`-`15` | PMP アドレス |
| 0xB00 / 0xB02 | `mcycle` / `minstret` | 書き込み可。書き込みはその命令の加算に優先する |
| 0xC00 / 0xC01 / 0xC02 | `cycle` / `time` / `instret` | 読み出し専用。`time` は CLINT の `mtime` |
| 0xF11-0xF14 | `mvendorid` / `marchid` / `mimpid` / `mhartid` | 読み出し専用 |

スーパバイザモード:

| アドレス | CSR | 備考 |
|---|---|---|
| 0x100 | `sstatus` | `mstatus` をマスクして見たもの。実体は 1 つ |
| 0x104 / 0x144 | `sie` / `sip` | `mie`/`mip` を `mideleg` でマスクしたもの |
| 0x105 | `stvec` | `mtvec` と同じ 2 モード |
| 0x106 | `scounteren` | U がカウンタを読めるかどうか |
| 0x140-0x143 | `sscratch` / `sepc` / `scause` / `stval` | |
| 0x180 | `satp` | MODE は bare(0)と Sv39(8)のみ。それ以外の書き込みは無視 |

浮動小数点: 0x001/0x002/0x003 = `fflags`/`frm`/`fcsr`(10 章)。
デバッグ用 CSR(`dcsr`/`dpc`/`dscratch*`)はまだ無い。

**アクセスの可否**は 3 つの条件で決まり、どれも不正命令例外になる:

1. そのアドレスが実装されていない
2. アドレス bit[9:8] が現在の特権より上(`rd_denied`)
3. 書き込みなのにアドレス bit[11:10] が 11(読み出し専用)

これに加えて `satp` は S モードかつ `mstatus.TVM` のとき、
`cycle`/`time`/`instret` は `mcounteren`(S から)と `scounteren`(U から)が
許していないときに拒否される。

CSR 命令は**直列化**する。パイプラインが空になってから発行し、コミットするまで
次の命令を入れない。これにより `minstret`/`mcycle` の読み出し値が正確になり、
EX での CSR 読み出しが直前の CSR 書き込みを必ず見る。

## 8. 例外・割り込み

- トラップを取るのは **MA(コミット点)**。ストアは EX でキャッシュにデータを
  渡してしまうので、その 1 つ前の命令のトラップは、ストアがまだ EX にいる間に
  決まっていなければならない。MA で取れば `trap_taken` でストアの発行を止められる。
- 割り込みは **ID→EX の受け渡し**で命令に貼り付け、MA で取る。こうすると
  割り込みを付けられた命令はメモリアクセスも分岐も実行しないので、`mepc` が
  その命令を指す正確な割り込みになる。WFI だけは例外で、WFI 自身には貼らず
  次の命令に貼る(`mepc` が WFI の次を指すようにするため)。
- 優先順位は特権仕様に従う。同一命令で複数条件が立つ場合の順序:
  **命令アドレス不整列 → 命令アクセスフォールト → 命令ページフォールト →
  不正命令 → ブレークポイント → ロード/ストア不整列 → アクセスフォールト →
  ページフォールト**
- 割り込み: CLINT(`msip`/`mtime`/`mtimecmp`)を内蔵(`RTL/CPU/CPU_CLINT`)。
  外部割り込みは PLIC(後段)。レジスタ配置は SiFive CLINT と同じで、
  ベースアドレスからの相対で

  | オフセット | レジスタ | 幅 |
  |---|---|---|
  | 0x0000 | `msip` | 32bit(bit0 がソフトウェア割り込み) |
  | 0x4000 | `mtimecmp` | 64bit |
  | 0xBFF8 | `mtime` | 64bit |

  `mtime` は `TICK_DIV` サイクルごとに 1 進む(シミュレーションは 1、実機は
  クロックを分周して固定周波数にする)。割り込み線は `msip` と
  `mtime >= mtimecmp`。
- 委譲: `medeleg`/`mideleg` により S-mode へ委譲。委譲先が現在の特権より
  上になることはないので、条件は「委譲ビットが立っていて、かつ現在 M ではない」。
- **特権によって禁止される命令**(いずれも不正命令例外):

  | 命令 | 禁止条件 |
  |---|---|
  | `MRET` | M 以外 |
  | `SRET` | U、または S かつ `mstatus.TSR` |
  | `SFENCE.VMA` | U、または S かつ `mstatus.TVM` |
  | `WFI` | M 以外かつ `mstatus.TW` |

- `ECALL` の原因番号は現在の特権で決まる(U=8、S=9、M=11)。
- デバッグ: `ebreak` と外部からの halt 要求は `dcsr` に従ってデバッグモードへ。

## 9. 拡張の受け口

### 9.1 アクセラレータポート(カスタム命令)

`custom-0/1/2/3` をデコーダが横流しする。Rocket の RoCC 相当。

| 信号 | 内容 |
|---|---|
| `acc_req_valid/ready` | 発行 |
| `acc_req_funct7/rs1/rs2/rd`、`acc_req_xd/xs1/xs2` | 命令フィールドとオペランド |
| `acc_resp_valid/rd/data` | 結果(GPR への書き戻し) |
| `acc_busy` | `fence` 時の完了待ちに使う |

将来、アクセラレータ用のメモリポート(D$ の第 3 ポート)を足す余地を残す。

### 9.2 ベクタ拡張

- 発行/完了インタフェースを**可変レイテンシ・順不同完了**に対応させておく
  (最初の利用者は FPU の FDIV/FSQRT、10 章)。
- ベクタのロード/ストアは現状の 64bit D$ ポートでは帯域が足りないため、
  実装時に D$ ポートの拡幅(128/256bit)またはポート追加を検討する。

## 10. 浮動小数点ユニット (F/D)

### 10.1 方針

> **M4 での変更**: Rev-1 の計画では「疎結合 + スコアボード」としていたが、
> 実装時に **EX で待つ方式**(MDU と同じ)に変えた。理由と、元の計画に戻すときの
> 手順は 12.6 に書いた。以下 10.1 は元の考え方の記録。

FPU は整数パイプラインの中に埋め込まず、**独立した機能ユニット**として接続し、
可変レイテンシ・FP レジスタのスコアボードで依存を管理する。

そうできる理由は **RISC-V の浮動小数点演算がトラップしないから**である。
IEEE の例外(無効演算・ゼロ除算・オーバフロー・アンダフロー・不正確)は
`fflags` に積まれるだけで、例外を起こさない。したがって FP 命令が整数命令と
前後して完了しても**精密例外は壊れない**。トラップしうるのは FLD/FSD の
アドレス例外だけで、それは通常のロード/ストア経路(LSU)で扱う。

### 10.2 パイプラインへの接続

```
  ID        EX          FPU 内部(可変段数)                WB
  ─────────────────────────────────────────────────────────────
  FP RF 読み ─> 発行 ─> [FADD/FMUL/FMA : 3〜5 段        ] ─> FP RF 書き
                     └> [FDIV/FSQRT   : 反復、非パイプ ] ─┘
                     └> [比較/変換/符号 : 1〜2 段       ] ─> 整数 WB へ(10.2 表)
  FLD/FLW  : ID で発行 → LSU(D$)→ NaN-boxing して FP RF 書き
  FSD/FSW  : ID/EX で FP RF を読み、ストアデータとして LSU へ
```

| 結果の行き先 | 対象命令 | 接続 |
|---|---|---|
| FP レジスタ | 算術、変換(int→fp)、符号操作、FMIN/FMAX、FMV.W.X、FLD/FLW | FPU が完了時に直接書く |
| 整数レジスタ | FEQ/FLT/FLE、FCLASS、FMV.X.W、変換(fp→int) | 1 エントリのバッファ経由で整数 WB ポートを共有。整数側優先、衝突時は FPU が 1 サイクル待つ |
| メモリ | FSD/FSW | LSU のストアデータ源を GPR/FPR で選択 |

### 10.3 レイテンシとリソース(50MHz 目標、Artix-7)

| 演算 | 段数 | 備考 |
|---|---|---|
| FADD / FSUB | 3 | 指数合わせ → 加算 → 正規化 → 丸め |
| FMUL | 3 | 53×53 を DSP48E1 で 9〜12 個 |
| FMA(FMADD ほか 4 種) | 4〜5 | 乗算器と加算器を共有 |
| FDIV / FSQRT | 反復(倍精度で約 27 サイクル) | **非パイプライン**、同時 1 件のみ |
| 比較 / FCLASS / 符号操作 / FMV | 1 | |
| 変換(FCVT) | 2 | |

Arty A7-100T は DSP48E1 が 240 個、現状の使用は 0 個なので倍精度でも余裕がある。
50MHz(20ns)であれば各段に十分な余裕をとれる。

### 10.4 レジスタファイル

- 32 本 × 64bit。単精度は NaN-boxing して格納する(10.7)。
- **3 読み出し 1 書き込み**(FMA が rs1/rs2/rs3 を要求する)。FPGA では
  32×64bit の分散 RAM を 3 面ミラーして書き込みを全面に流す(約 200 LUT)。
- ストア(FSD/FSW)の読み出しは 3 本のうち 1 本を共有する。

### 10.5 ハザードと制御

| 項目 | 方式 |
|---|---|
| 依存 | FP レジスタごとの busy ビット(スコアボード)。ソースまたはデスティネーションが busy なら ID で停止(WAW も同時に防ぐ) |
| FDIV/FSQRT | 実行中は 2 件目を発行しない |
| `fcsr` / `fflags` / `frm` アクセス | FPU が空になるまで待つ(フラグ累積の順序を保つため) |
| `mstatus.FS` | 0 のとき FP 命令は**不正命令例外**。FP レジスタまたは fcsr を書いたら Dirty にする(Linux の遅延 FP コンテキスト切り替えに必須) |
| 丸めモード | 命令の `rm` フィールド。`rm=111` は `frm` CSR を使う。予約値は不正命令例外 |

### 10.6 フラッシュ・トラップとの関係

分岐予測ミスや例外でパイプラインをフラッシュするとき:

- **より若い** FP 命令は epoch タグで kill する(フェッチのリダイレクトと同じ仕組み)。
- **より古い** FP 命令は完了を待ってから例外処理に入る。`fflags` とレジスタ
  書き込みを取りこぼさないため。
- 割り込みも同様に、FPU が空になってから受け付ける。

### 10.7 NaN-boxing と特殊値

- 単精度値は上位 32bit を全 1 にして 64bit レジスタに格納する。FLW / FMV.W.X /
  単精度演算の結果は boxing する。
- boxing されていない値を単精度演算のソースにすると **canonical NaN** を生成する。
- **subnormal はハードウェアで完全に扱う**(flush-to-zero にしない)。自作 FPU で
  最もバグが出るのがここなので、10.8 の検証で担保する。

|---|---|---|
| F1 | FP RF、FLD/FLW/FSD/FSW、FSGNJ 系、FMV、FMIN/FMAX、比較、FCLASS、FCVT | 演算器抜きで**インフラ**(スコアボード、NaN-boxing、`mstatus.FS`、`fflags`、丸めモード)を動かす |
| F2 | FADD / FSUB / FMUL | |

### 10.9 自作するか既存の IP を使うか

| | 自作(推奨) | Berkeley HardFloat | FPnew (ETH) |
|---|---|---|---|
| 言語 | SystemVerilog(本プロジェクトの流儀) | Chisel 生成 Verilog(Rocket が使用) | SystemVerilog |
| ライセンス | — | BSD | SolderPad |
| 工数 | 大(IEEE-754 の細部) | 小 | 小〜中 |
| 制御 | 段数・面積を自分で決められる | 決め打ち | パラメータ豊富 |

本プロジェクトは「自分で作る」方針なので **自作 + TestFloat 検証**を第一候補と
する。工数が問題になった場合は F4(FDIV/FSQRT)だけ既存 IP に置き換える、
といった部分採用も可能な構成にしておく。

### 10.10 FPU を外す構成

パラメータ `HAS_FPU` で FPU を外せるようにし、`misa` の F/D ビットも落とす
(FPGA の面積実験や初期ブリングアップ用)。ただし Linux の標準 ABI は lp64d
(ハードウェア浮動小数点)なので、実機で Linux を動かす構成では FPU は必須。

### 12.1 進め方: パイプライン骨格から積む

「デコーダから積む」「骨格 + CSR から積む」の比較:

| | デコーダ先行 | **骨格 + CSR 先行(採用)** |
|---|---|---|
| 利点 | 単体テストが容易(命令語→フィールドの網羅比較)。uop 定義が早く固まる | 早期に**動く機械**が手に入り、以降すべてが end-to-end で検証できる。キャッシュ・デバッグ・バスとの**結合部**(本プロジェクトで最もリスクが高い所)を最初に叩ける |
| 欠点 | 長期間なにも動かない。パイプラインに合わない uop 定義を作り込むと手戻り | 最初は足場作りが多い。パイプライン構造を先に決める必要がある(本仕様で決めている) |

本プロジェクトは周辺(キャッシュ・デバッグ・FPGA フロー)が検証済みで、残る
リスクは結合部にある。したがって**骨格先行**を採り、デコーダは最初から
「独立モジュール + 単体テスト」として作り、拡張ごとにテーブルを足していく
(両方式の良いとこ取り)。

段間制御(M1 で確定した規則):

| 信号 | 定義 | 意味 |
|---|---|---|
| `stall_ma` | `ma_valid & ma_mem & ~lsu_resp_valid` | MA がキャッシュの応答を待っている |
| `stall_ex` | `stall_ma \| (ex_is_mem & ~lsu_accept)` | EX が進めない(応答待ち、またはキャッシュが要求を受け取らない) |
| EX→MA | `ex_advance` で転送、`~ex_advance & ~stall_ma` のときは **MA を空にする**(バブル) | EX が渡せないのに MA が空かないとデッドロックする |
| MA→WB | `~stall_ma` で転送、`stall_ma` のときは **WB を空にする**(バブル) | 同じ命令を二度リタイアさせない |
| EX のオペランド | EX がストールしている間は `ex_rs1_data/ex_rs2_data` に**フォワード値を取り込み続ける** | ストール中に MA/WB が先へ進み、フォワード元が消えるため |

フォワーディングは MA と WB の 2 経路。MA にロードがある場合は `ma_result`
(アドレス)ではなくキャッシュの応答 `lsu_resp_data` を出す。EX が進めるのは
`stall_ma` が下りたサイクル、すなわちロードの応答が出ているサイクルなので、
これで load-use が 1 バブルで解ける。

|---|---|
| `t01_alu` | 即値・レジスタ演算、シフト、LUI/AUIPC、32bit 形式、符号付き/符号なし比較、W 形式のシフト量 5bit |
| `t02_branch` | 6 種の分岐、JAL/JALR、ループ、前後方向ジャンプ |
| `t03_ldst` | 全サイズのロード/ストア、符号/ゼロ拡張、バイトレーン、負オフセット |
| `t04_hazard` | EX→EX、MA→EX、load-use、ストアデータ、ストール中のオペランド保持、分岐直後の依存 |

### 12.5 M3 の実装(完了)

| 拡張 | 実装 |
|---|---|
| M | `CORE_MDU`。EX の横に置き、EX が待つ。乗算 3 サイクル、除算は 1 サイクル 1 ビットで 32 または 64 サイクル |
| A | デコーダが `mem_cmd` をキャッシュのコマンドに割り付けるだけ。read-modify-write と予約はキャッシュ側(実装済み) |
| C | `CORE_DECOMP`(16bit → 32bit)と `CORE_IFU` のパーセル方式への作り直し |

**乗算器**: 符号なし 32×32 の部分積 4 個(FPGA の DSP に載る形)から 128bit を
組み立て、符号は後から引いて直す。

```
a * b (符号つき) = ua * ub - (a < 0 ? ub << 64 : 0) - (b < 0 ? ua << 64 : 0)
```

**除算器**: 復元法。ゼロ除算と唯一のオーバーフロー(-2^63 ÷ -1)は反復なしで答える。
32bit 形は被除数を上位に寄せてから 32 回まわす。

**C 拡張とフェッチ**: 命令が 4 バイト境界に乗らず、64bit フェッチ語をまたぐので、
フェッチキューは**命令ではなくパーセル(16bit)を並べる**。

| 仕組み | 内容 |
|---|---|
| `head_pc` | キュー先頭パーセルのアドレス。パーセルは順に積まれ一括で捨てられるので、エントリごとにアドレスを持たなくてよい |
| `push_pc` | 次に積むパーセルのアドレス。語の途中へリダイレクトしたとき、手前のパーセルを捨てる枚数がこれで決まる |
| 先頭の判定 | `p0[1:0] != 11` なら 16bit 命令、そうでなければ 2 パーセル必要 |

IALIGN が 16 になるため、`mepc` は bit0 だけを落とし、分岐先の不整列例外は
(JALR が bit0 を落とすので)起こり得なくなる。

|---|---|
| riscv-tests `rv64um-p-*` | 13/13 PASS |
| riscv-tests `rv64ua-p-*` | 19/19 PASS(`amocas` は Zacas なので対象外) |
| riscv-tests `rv64uc-p-rvc` | PASS |
| `t08_rvc` | 圧縮命令の意味、語境界をまたぐ 32bit 命令、語の途中への分岐、C.EBREAK、不正な圧縮命令の `mtval` |
| `t09_muldiv` | 乗除算の符号、ゼロ除算、オーバーフロー、32bit 形 |
| `t10_atomic` | LR/SC(成功・失敗・途中のストアで予約が切れる)、全 AMO の 32/64bit、不整列 |

riscv-tests は全セットを **C 付きでビルド**しているので、命令列そのものが
16bit と 32bit の混在になり、フェッチ経路が常に試されている。

バグ注入は 76 種、背圧あり/なしの両方で全て検出する。

### 12.6 M4 の実装(完了)

| モジュール | 内容 |
|---|---|
| `CPU_FPU/FPU_ROUND` | 正規化・丸め・詰め込み。**丸めるものは全部ここを通る** |
| `CPU_FPU/CORE_FPU` | F/D の全演算 |
| `CORE_FRF` | FP レジスタファイル(32×64、3R1W) |
| `CORE_DEC` / `CORE_DECOMP` | F/D 命令、C.FLD/C.FSD/C.FLDSP/C.FSDSP |
| `CORE_CSR` | `fflags`/`frm`/`fcsr`、`mstatus.FS` と `SD` |

**接続方式を変えた**: 計画ではスコアボードによる疎結合だったが、**EX で待つ方式**
にした。理由:

- 単発発行のインオーダコアでは、FP 命令の直後の命令はたいてい結果に依存する。
  疎結合で得られるのは独立な整数命令が続く場合だけで、利得が小さい。
- スコアボード + フラッシュ時の kill/drain + epoch タグ(10.6)は、FPU 本体より
  バグが出やすい。**いちばん危ないのは演算器ではなく制御**という判断。
- MDU で同じ形が既に動いていて検証済み。
- 疎結合化は `CPU_CORE` 側の話で、**FPU のデータパスには手を入れずに後から**
  できる。戻すときは (1) FP レジスタごとの busy ビット、(2) 完了時の FRF 書き
  ポート調停、(3) フラッシュ時の epoch、(4) `fcsr` アクセス時のドレイン、の
  4 つを足す。

**演算器の構成**

| 単位 | 方式 | サイクル |
|---|---|---|
| FADD/FSUB/FMUL/FMA 4 種 | **積和 1 本のデータパス**。`a*b+c` を 128bit の共通枠で厳密に計算し、**丸めは 1 回** | 4 |
| FDIV | 復元法。倍精度 128 ビット、単精度 64 ビット | 64〜128 |
| FSQRT | 復元法(2bit/反復の平方根) | 64 |
| 比較・分類・符号操作・転送・変換 | 組合せ + 1 段 | 1 |

積和を 1 本にしたのは工数のためではなく、**それが fused の定義だから**。
加算器と乗算器を分けると二重丸めになり FMA にならない。FADD は `a*1.0+c`、
FMUL は加数なしとして同じ経路を通る。

除算の商は、**最も深い subnormal の丸め位置まで**ビットを作る必要がある
(倍精度で最大 54 ビット余分)。丸め器の入力を 128bit にしてあるのはこのため。
平方根は入力が subnormal でも結果は必ず正規数(最小 subnormal の根は 2^-537)
なので 64 ビットで足りる。

**検証**: `SIM/SIM_FPU` で **Berkeley SoftFloat(RISCV 特殊化)**と突き合わせる。
既定 45 万チェック、`make long` で約 494 万チェック。全演算 × 両精度 ×
丸め 5 モード × 特殊値の総当たり + ランダム。結果ビットと例外フラグ 5 ビット全部。

参照モデルが見つけたバグ(いずれも手書きテストでは気づけないもの):

| 症状 | 原因 |
|---|---|
| subnormal の値が 2 倍ずれる | 正規化後の指数が 1 ずれていた(`(1-bias)-sh` と `-bias-sh`) |
| 等しい値で `flt` が 1 | 符号での反転を、仮数が等しい場合にも適用していた |
| NaN-boxing されていない値の FSGNJ/FMIN | 転送命令以外は canonical NaN にしなければならないのを見落とし |
| 丸めで最小正規数に到達したとき UF が立たない | tininess を**詰め込んだ指数**で判定していた。正しくは「指数範囲が無制限なら」という仮定での丸め結果で判定する |

**コア結合で見つかったバグ**(riscv-tests が検出):

| 症状 | 原因 |
|---|---|
| `flw` の直後の `fmul` が canonical NaN | **MA がキャッシュ応答待ちの間に FPU が古いオペランドで計算を開始**していた。MDU も同じ穴があり、M3 から潜在していた |
| `csrs mstatus, FS` の直後の FP 命令が不正命令 | デコーダが `mstatus.FS` と `frm` を読むので、CSR 書き込み後の直列化が必要だった(SMP 準備のときに「冗長」として外していたものを戻した) |
| `c.fld` が不正命令 | D 実装前に予約扱いにしていた圧縮命令を有効化していなかった |

**riscv-tests**: `rv64uf` 11/11、`rv64ud` 12/12。全体で 124 PASS。

**シミュレータ由来の落とし穴**: `always @(*)` から**出力引数つき task** を呼ぶと、
Icarus Verilog はその出力も感度リストに入れてしまい、ブロックが自分で自分を
起こし続ける。コア全体が約 1000 倍遅くなり、1 サイクルに数秒かかるようになった。
`unpack` の呼び出しだけ感度リストを明示して回避している(task は入力 2 本しか
読まないので、明示しても正確)。キャッシュで `always_comb` を避けているのと同じ
たぐいの制約。

**未了**: `HAS_FPU` パラメータ(10.10)はまだ入れていない。除算は radix-2 のままで、
倍精度 1 回に 128 サイクルかかる。どちらも必要になった時点で。

### 12.7 M5 の実装(完了)

S/U 特権、PMP、Sv39 MMU。3 段に分けて、それぞれ回帰を通してからコミットした。

**第 1 段: 特権モード**(`CORE_CSR` / `CORE_DEC` / `CPU_CORE`)

特権レベルは `CORE_CSR` に置いた。**それを変えるもの(トラップ・MRET・SRET)が
すべてここで決まる**から。パイプラインは読むだけ。

- `mstatus` に S 側のフィールドとトラップ用のビット(MPRV/SUM/MXR/TVM/TW/TSR)。
  `sstatus` は**同じレジスタをマスクして見たもの**で、複製ではない
- `medeleg`/`mideleg`。委譲されるのは「ビットが立っていて、かつ発生元が M でない」
  ときだけ。委譲先が発生元より上になることはない
- 割り込みは「自分より下のレベルでは無条件、自分のレベルではそのレベルの
  グローバル許可ビット次第」。**U モードでは `sstatus.SIE` が 0 でも S の割り込みが
  入る**(SIE は自分のレベルでしか止めない)
- `SRET` と `SFENCE.VMA` をデコーダに追加。`SFENCE.VMA` は `fence.i` と同じく
  コミット後に再フェッチする(フロントエンドが使い終わった変換を変えるため)

riscv-tests の期待値が 2 つ逆になった: `mstatus.MPP` は 3 固定ではなくなり、
`satp` は存在するようになった。

**第 2 段: PMP**(`RTL/CPU/CPU_MMU/MMU_PMP` と `CORE_MMU`)

`CORE_MMU` を先に**器として**作り、パイプラインが使うアドレスは全部ここを通す
形にした(この時点の変換は恒等写像)。そのため第 3 段で TLB とウォーカを足す
ときに `CPU_CORE` 側の変更がほとんど要らなかった。

命令面のためにフェッチユニットを作り直した。**フェッチは投機的なので、
フォールトを見つけた場所で例外にしてはいけない**。パーセルと並べてキューに
書き込み、それを実際に使う命令が ID で例外にする。フォールトしたフェッチは
キャッシュには出さない。フォールトのコードは最初から 2 ビットにしてあるので、
第 3 段のページフォールトで書き直しにならなかった。

**第 3 段: Sv39**(`MMU_TLB` / `MMU_PTW`、`CORE_MMU` 拡張)

- TLB はフルアソシアティブ、**権限ビットは読んだまま持ち、毎回の引き当てで
  判定する**。特権・SUM・MXR は何も無効化されずに変わるので、書き込み時に
  判定すると古くなる
- ウォーカは D$ ポートを借りる。**LSU に何も飛んでいないときだけ起動**し、
  終わるまで離さない。借りている間はデータ面に「今サイクルは出せない」を返す。
  どのみちアクセスは出せないし、こうすると PMP チェッカもウォーカに回せる
- A/D はハードウェア更新しない(6.2)

**コア結合で見つかったバグ**:

| 症状 | 原因 |
|---|---|
| `rv64ui-v-st_ld` / `rv64uc-v-rvc` が無限ループ | **ページ境界をまたぐ 32bit 命令**で、後半のページだけがフォールトしたとき、`stval` に命令の先頭アドレス(前半のページ)を入れていた。OS は正しいページを直せず同じ例外を繰り返す。`mepc` は命令の先頭だが `stval` は**フォールトした側**でなければならない |

**検証**:

| 環境 | 内容 |
|---|---|
| `SIM/SIM_MMU/tb_PMP` | 仕様からバイト範囲で書き起こした独立モデルと 50 万ケース照合 |
| `t12_priv` | M → S → U を歩く。rv64si が触らない U モード、T ビット、委譲された割り込み |
| `t13_pmp` | 3 つの権限、番号の小さいエントリが勝つこと、ロック、MPRV |
| `t14_mmu` | 手書きページテーブルで 3 レベル、1G/2M スーパページ、権限ビット全種、`sfence.vma` |
| **riscv-tests `v` 環境** | **109 本**。S モードで Sv39 を立てて U モードで走らせ、ページを要求に応じて割り当てる。全命令が変換を通り、ページテーブルが何千回も歩かれる |
| riscv-tests `p` 環境 | 132 本(`rv64si` 7/7、`rv64mi-p-pmpaddr` 込み) |

`v` 環境のために `CORE_MEM_MODEL` が**物理アドレスで応答する**ようになった。
それまでは `*_req_paddr` を無視して仮想アドレスで答えていたので、MMU を入れた
とたんにデータが見つからなくなった。テストベンチも HTIF のコンソール
(`tohost` の上位バイトがデバイス番号)を解釈する。

バグ注入(125 種)にも `v` 環境のテストを 1 本入れてある。自作テストはすべて
1G ページ 1 枚の上で走るので **ITLB が外れることがなく**、D$ ポートを
パイプラインとページテーブルウォーカで取り合う経路が動かない。4KiB 単位で
マップされた `v` 環境のテストだけがそこを踏む。

**未了**: デバッグ論理の Access Memory はまだハートと同じ変換を通らない(11 章)。
