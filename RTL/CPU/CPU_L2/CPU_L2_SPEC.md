## 1. 目的と効果の見込み

実機の PMU で Linux の負荷を数えると(`BENCH.md` 14 章)、**カーネルが主の負荷はサイクルの
5〜7 割を L1 のミス待ちに使っている**。I$ ミスは 1000 命令あたり 19〜61、D$ ミスは 15〜31
(CoreMark はそれぞれ 0.49、0.16)。カーネルのコードとデータは 16 KB の L1 に収まらない。

L1 のミス 1 回の重さは、理想的なメモリで 12〜13 サイクル(`CPU_CACHE_SPEC.md` 8.4、64 B を
8 ビートで受ける)、実機で 30〜50 サイクル(PMU から逆算)。差の **20〜35 サイクルが LiteDRAM
までの往復**で、L2 がヒットすればそこが 2〜3 サイクルになる。

見込み(L1 のミスの 6〜8 割が L2 にヒットし、1 回 約 20 サイクル縮むとして。
`BENCH.md` 14 章の数字から):

| 負荷 | L1 ミス / 1000 命令 | CPI | 減るサイクル | 速くなる |
|---|---|---|---|---|
| `tftp` | 93 | 4.80 | 約 27 % | 約 1.37 倍 |
| `ext4read` / `sdread` | 65〜70 | 4.0〜4.5 | 約 22 % | 約 1.28 倍 |
| `ls -lR` | 47 | 3.08 | 約 21 % | 約 1.27 倍 |
| `forkexec` | 37 | 2.74 | 約 19 % | 約 1.23 倍 |
| `gunzip` / `awk` | 4〜5 | 1.4〜1.7 | 約 4 % | |
| `md5sum`(流れる読み出し) | 4 | 1.22 | 1〜2 % | (先読みなら効く。8 章) |
| CoreMark | 0.6 | 1.13 | ほぼ 0 | |

ヒット率は実装して測るまで分からない。L2 用の性能カウンタのイベントを足して実機で数える(7 章)。

## 2. 置き場所とつなぎ方

```
  CPU_TOP
  ┌───────────────────────────────────────────────────────────────┐
  │ CPU_CORE ─ i_* / d_* ─ CPU_CACHE(I$ / D$ ─ BUS_ARB)          │
  │                               │ AXI4 64 bit(メモリバス)       │
  │                               ▼                               │
  │                        CPU_L2(新設) ────────────────────────────┼─ m_axi4 → LiteX
  │                                                               │   AXIUpConverter(64→128)
  │ CPU_DBG ─ DBG_CACHE ─▶ D$ の第 2 ポート                        │   → LiteDRAMAXI2Native
  │ DMA ポート ───────────▶ D$ の第 2 ポート                        │   → LiteDRAM(DDR3 16 bit)
  │                        AXI4-Lite(周辺、キャッシュしない)──────────┼─ m_axil(L2 を通らない)
  └───────────────────────────────────────────────────────────────┘
```

- **`CPU_CACHE` のメモリバス(AXI4、64 ビット)と `CPU_TOP` の `m_axi4` の間**に、AXI4 の
  スレーブとマスタを 1 つずつ持つブロックとして挟む。コア・L1・`BUS_ARB`・LiteX の側は何も
  変えない(`core.py` も LiteX のチェックアウトも変更なし)。
- **主記憶へ行くものはすべてここを通る**: I$ / D$ の fill、D$ の書き戻し、SD カードの DMA
  (D$ の第 2 ポート経由)、デバッガのメモリアクセス(同)。ほかに主記憶を触る経路は無い
  (Ethernet のバッファは SoC の SRAM)。したがって **L2 は作りからして一貫している**。
  後始末(フラッシュの命令、無効化)は要らない。
- LiteX 自身の L2(`--l2-size`)は SoC バスの側にあり、CPU のメモリバスはそれを通らない。
  使えない(`build_soc.sh` の注記、`BRINGUP.md`)。
- `CPU_TOP` のパラメータ `L2_SIZE`(0 なら L2 なしでそのままつなぐ)。L2 の有無を比べる
  ビルド、デバッグ論理の単体ビルド(`FPGA/ARTY_A7_100T`)のため。

## 3. 方式(案)

| 項目 | 案 | 理由・代案 |
|---|---|---|
| 容量 | **256 KB**(パラメータ。128 KB にもできる) | ブロック RAM が 94 タイル余っている(5 章)。カーネルの頻繁に使うコードとデータは数百 KB と見て大きめ。タイミングや配置が苦しければ 128 KB |
| 連想度 | **4 ウェイ** | L1(4 ウェイ、1 ウェイ 4 KB の VIPT)の索引の偏りを受け止める。8 ウェイはタグ比較とウェイ選択が倍、ダイレクトマップは衝突が多い |
| 行 | **64 B**(L1 と同じ) | L1 の fill 1 回 = L2 の 1 行。行を分けたり継いだりしない |
| 置き換え | **疑似 LRU**(木構造、1 セット WAYS−1 = 3 ビット、LUT RAM)。無効なウェイがあればそれを先に使う | 代案は乱数(`REPLACE_RANDOM=1`、8 ビットの LFSR をミスごとに進める)。乱数でも大差なければそちら |
| 包含関係 | **非包含**(L1 にあるものが L2 にあるとは限らない) | 包含にすると L2 の追い出しで L1 を無効化する経路が要る。一貫性は 2 章の理由で不要 |
| 書き方 | **書き戻し**。行全体の書き込み(D$ の書き戻し)は読まずに確保(ヒットでもミスでも L2 に書いてダーティ)。**一部だけの書き込み**(デバッガのライトスルー `STWTHR`)は**ライトスルー・非割り当て**: メモリへ必ず書き、L2 にあればその語も更新する(ダーティにはしない) | 一部だけの書き込みはデバッガだけ。ライトスルーにしておけば、デバッガが書いたメモリは L2 を消しても残る(`SIM_OCD` の「RAM kept over ndmreset」、`CPU_CACHE_SPEC.md` 4.7 と同じ考え) |
| 同時に扱う要求 | **1 本ずつ**(到着順)。追い出す行の書き戻しは **1 行の追い出しバッファ**に入れて、fill を先に済ませる | L1 の MSHR 2 本・書き戻しバッファ 2 本の重なりは L2 で直列になるが、コアは順番どおりに 1 命令ずつなので失うものは小さい。ミス中のヒット(hit-under-miss)は 8 章の拡張 |
| メモリ側 | AXI4 64 ビット、8 ビートのバースト(今と同じ) | LiteX 側を変えない。128 ビット(LiteDRAM の幅)は 8 章の拡張 |
| リセット | CPU のリセット(システムリセット、`ndmreset`)で**中身を捨てる**。リセット後、セット数のサイクル(256 KB で 1,024)かけてタグの有効ビットを消し、その間は要求を待たせる。有効・ダーティのビットはタグと同じブロック RAM に置く(フリップフロップにすると 1,024 × 4 × 2 = 8,192 個と 1,024 対 1 の選択になる。その代わり 1 サイクルでは消せないので、この消去が要る) | L1 と同じ扱い。ダーティ行はリセットで失われるが、それは L1 の今と同じ。デバッガの書き込みはライトスルーなので残る(上)。代案は 9 章 |

## 4. 動作

L2 が受ける要求は 3 種類だけ(`CPU_CACHE` の作り。AMO や LR / SC は D$ の中で済む)。

| 要求 | 出す側 | ヒット | ミス |
|---|---|---|---|
| 行の読み出し(AR、8 ビート) | I$ / D$ の fill | L2 から 8 ビートを返す | 置き換える行を選ぶ。ダーティなら追い出しバッファへ。メモリから 8 ビート読んで、**届いた順に L1 へも返しながら**(fill の待ちを延ばさない)L2 に書く。追い出しバッファはその後メモリへ書く |
| 行の書き込み(AW、8 ビート、全バイト有効) | D$ の書き戻し | その行に上書き、ダーティ | 置き換える行を選び(ダーティなら追い出し)、読まずに書く、ダーティ |
| 一部の書き込み(AW、1 ビート、ストローブ) | デバッガのライトスルー | メモリへ書く。L2 のその語もストローブで更新(ダーティのまま / きれいのまま変えない) | メモリへ書くだけ(確保しない) |
| 一部の読み出し(AR、行の中の INCR、1〜8 ビート) | (今は無い) | 求められたビートだけ返す | 行全体を fill し、求められたビートだけ返す |

AW のバーストが「行の先頭から 8 ビート」なら行の書き込み(D$ はいつも全バイトを有効にして
送る)、それ以外はすべて一部の書き込みとして扱う。

**順序**。1 本ずつ到着順に処理する(AR と AW が同時に来たら交互)。メモリを使う要求(読み出しの
ミス、一部の書き込み)と、ダーティな行を追い出す要求は、**追い出しバッファが空になるまで待つ**。
バッファにある行はもう配列に無いので、その行への次のアクセスは必ずミスし、書き出しが終わって
からメモリを読む。これで同じ行の書き戻しと読み出しの追い越しは起きない。設計案にあった
「バッファから答える」経路は作らなかった(同じ行をすぐ読み直すのはまれで、比較器と選択が
増えるだけ)。

**ヒットの流れ**(行の読み出し、64 ビット × 8):

| サイクル | |
|---|---|
| t | AR を受ける。索引でタグとデータのブロック RAM を読む(4 ウェイ同時) |
| t+1 | タグ比較 → ヒットしたウェイを選ぶ(1 段レジスタ) |
| t+2 | 1 ビート目(R)。以後 1 サイクル 1 ビート、t+9 で 8 ビート目(RLAST) |

L1 から見ると、今のミス(理想的なメモリで 12〜13 サイクル)に 2 サイクル足した 14〜15
サイクル。実機の 30〜50 サイクルより 15〜35 サイクル短い。

**ミスの流れ**。メモリへの AR を出し、返ってくるビートを L1 へ流しながらデータ RAM に
書き、最後にタグを書く。L1 から見た遅延は **+3 サイクル**(AR の受け付け、タグ比較、R の
FIFO。`SIM_L2` で測定: メモリの AR → R が 2 サイクルのとき、L2 の AR → 最初の R は 5
サイクル)。設計案の見込み(+1〜2)より 1〜2 サイクル多いが、ヒットで縮む 20〜35 サイクルに
比べて小さい。ダーティな行を追い出すときは、メモリへの AR を先に出してから 8 語を追い出し
バッファへ写す(8 サイクル)。この間はメモリの往復(実機で 20〜35 サイクル)に隠れる。

### 4.1 実装の形(`CPU_L2.sv`)

| 部分 | 中身 |
|---|---|
| 主の状態機械 | `M_INIT`(消去)→ `M_IDLE`(受け付け。タグを読み、読み出しなら最初の語も読む)→ `M_CMP`(比較。ヒットなら 1 ビート目を出し 2 語目を読む)→ `M_RHIT`(ヒットを 1 サイクル 1 ビート)/ `M_WAIT`(追い出しバッファ待ち)/ `M_VCOPY`(ダーティな行をバッファへ)/ `M_FILL` / `M_WLINE` / `M_PW_AW`・`M_PW_W`・`M_PW_B`(一部の書き込みを素通し)/ `M_BRESP` |
| R の FIFO | 4 段。ID をビートごとに持つ。前の読み出しのビートが残っている間は次の AR を受けない |
| 追い出しバッファ | 1 行(512 ビット)と、それをメモリへ書く別の状態機械(`D_AW` / `D_W` / `D_B`)。ID は `DRAIN_ID`。一部の書き込みの素通しとは AW / W / B を取り合わない(一部の書き込みはバッファが空になるまで待つ) |
| 配列 | タグ: `L2_TAG_ARRAY`(ウェイごとに {有効, ダーティ, タグ} のブロック RAM)。データ: `CACHE_DATA_ARRAY`(L1 と同じ、語単位でストローブ付き)。疑似 LRU: LUT RAM(リセットの無いプロセスで書く) |
| PMU | `ev_read`(AR を受けたサイクルに 1)、`ev_miss`(読み出しのミスが分かったサイクルに 1) |
| パラメータ | `SIZE_BYTES`(256 KB)、`WAYS`(4、2 のべき乗。1 も可)、`REPLACE_RANDOM`(0)、`ADDR_WIDTH`(40)、`ID_WIDTH`(4)、`DRAIN_ID`(0) |

## 5. 資源とタイミング

見積もり(設計案)と、L2 単体を Vivado で合成・配置配線した実測(2026-10-06、`FPGA/L2_OOC`、
256 KB・4 ウェイ・疑似 LRU、out of context、50 MHz)。

| 資源 | 見積もり(256 KB) | **単体の実測** | 今(`BENCH.md` 13 章の版) | 合計(実測から) |
|---|---|---|---|---|
| ブロック RAM | データ 64 + タグ 2 タイル | **68**(データ 64、タグ 4: 1 ウェイ 1,024 × 26 ビットが RAMB36 1 個) | 40.5 | 108.5 / 135(80 %) |
| LUT | 2,500〜4,000 | **1,078**(ほかに疑似 LRU の LUT RAM 12 個) | 45,598 | 46,676(73.6 %) |
| FF | 1,500〜2,500 | **991**(追い出しバッファ 512、R の FIFO 約 280 を含む) | 27,006 | 27,997(22.1 %) |
| スライス | | **659**(全体ではまわりの論理と分け合うので、これより少なく増える) | 88.6 % | 92.8 % 以下 |
| DSP | 0 | 0 | 32 | |

LUT は見積もりの半分以下だった。データのウェイ選択(64 ビット × 4 → 1)と AXI の両側が
思ったより小さく、データ配列は 1 ウェイ 16 個のブロック RAM を 4 ビットずつの幅に分けて
並べる形になり、出力の選択が要らない。

- **タイミング**(実測): レジスタ間の WNS **+5.977 ns**(周期 20 ns)、ポートの両側に周期の
  30 % の遅延を置いた全体の WNS +3.953 ns、WHS +0.161 ns。最悪の経路は `M_CMP` の
  「タグのブロック RAM の出力(2.45 ns)→ タグ比較(CARRY4)→ `hit_any` → `cmp_iss`(2 語目の
  読み出し)→ データ配列 64 個の読み出し許可」で、論理 7 段、13.5 ns のうち配線が 9.1 ns
  (最後の許可の配線が 3.8 ns、ファンアウトは 64 個のブロック RAM)。全体に組み込むとブロック
  RAM がダイの全部の列に散らばり、この配線が延びる。足りなくなったら、`M_CMP` の読み出し許可を
  ヒットと無関係にする(ミスでも読んでよい)とこの経路から `hit_any` が外れる。
- L2 はメモリバスの上にだけあり、コアの最悪経路(EX の分岐比較 → IFU、`TIMING.md` 31 章)とは
  交わらない。
- **スライス**: いま 88.6 %(`ROADMAP.md`)。L2 単体が 659 スライス(全 15,850 の 4.2 %)なので、
  入れても 92.8 % 以下。これが C2(FPU のパイプライン化)に残る余地を決めるので、全体に
  組み込んだ版で実測してから C2 の予算を決める(10 章)。

---|---|---|---|---|
| ブロック RAM | データ 64 タイル(4 ウェイ × 64 KB、RAMB36 は 4 KB)+ タグ 2 タイル | 32 + 2 | 40.5 | 約 107 / 135(79 %) |
| LUT | 2,500〜4,000(制御、タグ比較 4 本、ウェイ選択 64 ビット × 4、AXI の両側、追い出しバッファ) | 同じ | 45,598 | 48,000〜50,000(76〜79 %) |
| FF | 1,500〜2,500(追い出しバッファ 512 ビットを含む) | 同じ | 27,006 | 約 23 % |
| DSP | 0 | 0 | 32 | |

- **タイミング**: L2 はメモリバスの上にだけあり、コアの最悪経路(EX の分岐比較 → IFU、
  `TIMING.md` 31 章)とは交わらない。ブロック RAM の読み出しはレジスタで受ける。気を付けるのは、
  66 タイルのブロック RAM がダイの複数の列に散らばり、L2 の制御からの配線が長くなること。
  データのウェイ選択の後に 1 段のレジスタを置く(上の t+2)。
- **スライス**: いま 88.6 %(`ROADMAP.md`)。+2,500〜4,000 LUT で 92〜94 % 程度になる見込み。
  これが C2(FPU のパイプライン化)に残る余地を決めるので、L2 を入れた版で実測してから
  C2 の予算を決める(10 章)。

## 6. 一貫性・リセット・デバッグとの関係

- **DMA、デバッガ、fence.i**: すべて D$ を通るので、L2 から見ると普通の fill と書き戻し
  (`fence.i` は D$ のダーティ行を書き戻し、I$ はその後 L2 から fill する。L2 は I$ と D$ で
  共通なので新しい内容が見える)。
- **キャッシュしない領域**(`MEM_BASE` 未満、AXI4-Lite)は L2 を通らない。
- **`ndmreset` / `hartreset`(デバッガの CPU リセット)**: 3 章のとおり中身を捨てる。OpenOCD の
  `reset halt` の後、BIOS は空の L2 から始まる。BIOS は ROM(`0x1000_0000`、`MEM_BASE` 未満)
  で動くので L2 を通らず、消去(1,024 サイクル、50 MHz で約 20 µs)は BIOS が主記憶を使う
  前に終わる。
- **電源投入**: 同じく消去してから要求を受ける。

## 7. 性能カウンタ

`CPU_CORE_SPEC.md` 決定 69 のイベントに 2 つ足す(`HPM_EVENTS` 18 → 20)。L2 から `CPU_TOP`
経由でコアへ(L1 の `ev_ic_refill` / `ev_dc_refill` と同じ形)。

| 番号 | イベント | perf |
|---|---|---|
| 18 | L2 への行の読み出し(L1 の fill) | `LLC-loads`(デバイスツリーの `pmu` ノードでキャッシュイベント 0x10010 に対応させる)、`r12` |
| 19 | そのうち L2 のミス | `LLC-load-misses`(0x10011)、`r13` |

`workload.sh` に L2 のヒット率の列を足す。

## 9. 未決事項

1. **容量**: 256 KB で始め、配置・タイミングが苦しければ 128 KB。ブロック RAM の余裕だけなら
   256 KB は入る。
2. **置き換え**: 疑似 LRU と乱数を、実機の `workload.sh` で比べて決める(パラメータで両方持つ)。
3. **CPU のリセットで中身を捨てるか**: 案は捨てる(L1 と同じ)。残す案は、L2 の配列を
   `ndmreset` の外に置き、AXI のやり取りだけをリセットする。ダーティ行が失われないが、
   リセットの途中で止まった AXI のやり取りの後始末が要る。今のところ利点が小さい。
4. **追い出しバッファを 1 行で足りるか**: D$ の書き戻しと fill が続けて来る形(`CPU_CACHE_SPEC.md`
   8.4 の「ダーティ追い出し」)で詰まらないかを、段階 3 の SIM_SYS(性能の内訳)と実機の PMU
   で見る。単体の検証では正しさだけを見た(11 章)。

## 11. 単体の検証(`SIM/SIM_L2`)

`tb_L2.sv` は `CPU_L2` の前に CPU_CACHE の役をするマスタ、後ろにメモリのモデル
(`SIM_CPU/AXI4_SLAVE_MEM.sv`)を置く。参照はマスタから見えるべきメモリの平らな像で、L2 を
通して読んだビートはすべてこれと比べ、書き込みは B が返った時点で像に入れる。

| 節 | 中身 |
|---|---|
| 1 指示 | ミスの後のヒット(メモリの AR の数、PMU のパルス数)。**ヒットの時間**: 最初のビートが AR の 2 サイクル後、8 ビートが 8 サイクルで続く(続けて 2 回)。ミスの遅延の表示(4 章)。行の書き込みのミスはメモリを読まない。1 セットに WAYS+1 本のダーティな行(追い出しと書き出し)。ダーティな行への一部の書き込み(メモリにそのバイトがあること、行にも入ること)。行の中の短い読み出し。L2 に無い行への一部の書き込み(確保しない)。**置き換え**: 空のセットを順に埋めるとウェイ 0 が先に出ること(疑似 LRU)、きれいな行の追い出しでメモリへ書かないこと。**書き出しを止めた状態**: メモリの AWREADY または WREADY を 40 サイクル止め、追い出しバッファに行がある間に、その行の読み出し(きれいな行を置き換える形で)、その行への一部の書き込み、ダーティな行を置き換える行の書き込みが、待つこと |
| 2 ランダム | 読み出し 2 本(ID 2 と 3)と書き込み 1 本のスレッドが同時に。行の読み出し、行の中の短い読み出し、行の書き込み、ストローブがランダムな一部の書き込み。行は「L2 より小さい窓」「4 つのセットの間で衝突」「どこでも」から選ぶ。スレッドの間では同じ行を同時に使わない。RREADY / BREADY / WVALID はランダム |
| 3 ランダム + メモリの停止 | 同じことを、メモリのモデルの READY をランダムに落とし、B / R をランダムに遅らせて |
| 4 読み戻し | 全行を L2 越しに読んで像と比べる |
| 5 リセット | L2 をリセットし、メモリをバックドアで新しい模様に書き換え、全行を**逆順に**読む(4 で最後に読んだ行が L2 に残っているので、消去が効いていなければ古い内容が見える) |

メモリ側の AXI の規約違反(`protocol_err`)は 0 でなければならない。監視カウンタで止まりも
失敗にする。`AXI4_SLAVE_MEM` には、書き出しを途中で止める試験のために `w_hold`(WREADY を
止める)を足した(既定は 0。ほかの検証環境は変わらない)。

**パラメータの掃引**(`./sweep.sh`): 256 KB・4 ウェイ(本番)、同・乱数置き換え、128 KB・8
ウェイ、512 KB・4 ウェイ(メモリは L2 の 2 倍)、8 KB・4 ウェイ(追い出しが多い、操作 2 万回)、
同・乱数、4 KB・ダイレクトマップ、4 KB・2 ウェイ、16 KB・8 ウェイ(メモリは L2 の 16 倍)、
8 KB・4 ウェイの別の種 2 つ。**11 構成すべて PASS**(1 構成 98 万〜252 万チェック)。

**バグ注入**(`./bug_inject.sh`、8 KB・4 ウェイ): ダーティな行を捨てる、行の書き込みで
ダーティにしない(ヒット / ミス)、fill をダーティにする、追い出しバッファを待たない(読み出しの
ミス / 一部の書き込み / ダーティな行を置き換える行の書き込み / `M_WAIT`)、書き出しの語・番地・
ビート数の誤り、バッファを書き出しの途中で空とする、リセット後の消去をしない(2 種)、疑似 LRU の
向き、R の FIFO のあふれ(ヒット / fill)、FIFO にビートが残ったまま次の AR を受ける、一部の
書き込みでヒットした行を更新しない / ミスで別の行に書く / ストローブを無視、fill で頼まれて
いないビートを返す、RLAST、ウェイの選択、索引の取り違え、一部の書き込みを行の書き込みとする、
R の ID、PMU のミス、2 ビート目の語、fill で行を無効のままにする、タグ比較のビット落ち。
**31 種すべて検出**。

ここで見ていないこと: 主記憶の番地の上位ビット(メモリのモデルが小さいので、タグの上位ビットは
変わらない)、メモリからのエラー応答(`fill_err`)、L1 の本物の要求の並び(段階 3 の SIM_SYS)。
